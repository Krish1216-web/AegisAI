# 14. Planner Agent

The **Planner Agent** is responsible for decomposing the high-level goals generated by the Orchestrator into concrete, dependency-aware executable steps.

---

## 1. Planning Architecture

```text
Orchestrator ExecutionPlan
           ↓
    Planner Agent
  ├── Step Generation (LLM Decomposition)
  ├── Topological Validation (Cycle checking, duplicate checks)
  └── Permission Verification (Block disallowed actions)
           ↓
DetailedExecutionPlan (Pydantic validated step list)
```

---

## 2. Pydantic Plan Schema

```python
class PlanStep(BaseModel):
    step_id: str
    title: str
    description: str
    agent_type: AgentType
    action: str
    inputs: List[str]
    expected_output: str
    dependencies: List[str]
    priority: int
    estimated_duration: float
    can_run_parallel: bool
    requires_confirmation: bool

class DetailedExecutionPlan(BaseModel):
    steps: List[PlanStep]
```

---

## 3. Plan Validations
To guarantee execution safety, the Planner executes structural validations:
- **Circular Dependency Check**: Formulates step dependencies as a directed graph and executes cycle-detection DFS checks.
- **Duplicate IDs Check**: Ensures all steps possess unique ID names.
- **Validation of References**: Verifies that any dependency step ID exists.
- **Permission Check**: Matches scheduled actions (e.g., `github_commit`) against user context permissions, rejecting plans requesting restricted operations.
