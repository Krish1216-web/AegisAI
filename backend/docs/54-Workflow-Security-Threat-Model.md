# Phase 7.9: Workflow Security Threat Model

## Subsystem Overview
This document evaluates the 30 primary security threats for the AegisAI Workflow Automation Subsystem, detailing attack scenarios, implemented mitigations, verification test suites, test outcomes, and residual limitations.

---

## Threat Matrix & Verification Status

| ID | Threat | Attack Scenario | Implemented Mitigation | Verification Test | Result | Remaining Limitations |
|---|---|---|---|---|---|---|
| **T-01** | **IDOR** | User modifies workflow ID in URL/payload to view or mutate another workspace's workflow. | Strict tenant isolation checks enforcing `workspace_id == current_user.workspace_id` on all CRUD and execution endpoints. | `test_workflow_tenant_isolation.py` | **VERIFIED** | None within single workspace scope. |
| **T-02** | **Cross-Tenant Workflow Access** | Malicious tenant crafts API call to read another tenant's DAG topology. | Database queries filter by `Workflow.workspace_id == caller_workspace_id`. Cross-tenant queries return 404 / empty. | `test_workflow_tenant_isolation.py` | **VERIFIED** | Workspace boundary is absolute. |
| **T-03** | **Cross-Tenant Execution Access** | Attacker queries execution logs or cancels runs belonging to a different tenant. | `WorkflowExecution` queries join and filter by `workspace_id`. | `test_workflow_tenant_isolation.py` | **VERIFIED** | Enforced at service and ORM layer. |
| **T-04** | **Unauthorized Workflow Execution** | Unauthenticated user triggers execution of a sensitive workflow. | Endpoint protected with JWT `get_current_user` dependency and rate limiting. | `test_workflow_api.py` | **VERIFIED** | Unauthenticated requests receive 401. |
| **T-05** | **Unauthorized Modification** | User modifies an archived or read-only workflow. | Status checks reject modifications if `Workflow.status == ARCHIVED` or version conflict occurs. | `test_workflow_atomic_update.py` | **VERIFIED** | Version bumping rejects concurrent overwrites. |
| **T-06** | **Unauthorized Approval** | Non-approver attempts to approve or reject a workflow paused on human approval. | `WorkflowApprovalService` validates user's workspace membership and role against `approver_roles` and `approver_users`. | `test_workflow_approval_rbac.py` | **VERIFIED** | Role matrix enforced. |
| **T-07** | **Self-Approval Separation** | Requester attempts to approve their own workflow execution request. | `requester_can_approve = False` policy rejects requester decision attempts. | `test_workflow_approval_rbac.py` | **VERIFIED** | Enforced unless policy explicitly allows. |
| **T-08** | **Workflow Recursion Attacks** | Workflow invokes itself as a sub-workflow, causing stack overflow. | `WorkflowNodeExecutor` detects cycle in `call_stack` and immediately raises recursion error. | `test_workflow_composition.py` | **VERIFIED** | Cycle detection halts execution. |
| **T-09** | **Workflow Depth Attacks** | Workflows chain sub-workflows deeply (A→B→C→D→E) causing resource exhaustion. | Hard ceiling `MAX_SUBWORKFLOW_DEPTH = 3` strictly enforced in execution context. | `test_workflow_composition.py` | **VERIFIED** | Maximum 3 levels allowed. |
| **T-10** | **Fan-Out / Task Explosion** | PARALLEL node creates unbounded downstream branches. | `max_concurrency` config (default 5, maximum 20) and `MAX_NODES_PER_EXECUTION = 50` limit DAG size. | `test_workflow_parallel_merge.py` | **VERIFIED** | Bounded DAG size. |
| **T-11** | **Concurrency Race Conditions** | Simultaneous executions of the same workflow overwrite node states. | Separate `WorkflowExecution` and `WorkflowExecutionNode` instances with unique UUIDs. | `test_workflow_concurrency.py` | **VERIFIED** | Executions are isolated rows. |
| **T-12** | **Duplicate Execution** | Client rapidly double-submits workflow trigger. | `idempotency_key` parameter checks for active running/pending execution. | `test_workflow_execution.py` | **VERIFIED** | Active execution returned. |
| **T-13** | **Scheduler Race Conditions** | Multiple worker threads pick up the same scheduled run simultaneously. | Concurrency policy (`concurrency_policy = skip`) drops firing if previous is `RUNNING` or `WAITING`. | `test_workflow_scheduler.py` | **VERIFIED** | Single execution per interval. |
| **T-14** | **Cancellation Races** | User cancels execution while a node is completing. | `cancel_execution()` sets status atomically to `CANCELLED`; downstream node loop terminates. | `test_workflow_execution.py` | **VERIFIED** | Downstream skipped. |
| **T-15** | **Secret Leakage in Outputs** | Secrets in input data or environment variables appear in execution logs. | `CredentialStore.redact_sensitive_dict()` recursively scrubs sensitive keys prior to DB commit. | `test_mcp_security_hardening.py` | **VERIFIED** | Sensitive keys masked as `[REDACTED]`. |
| **T-16** | **Error Payload Leakage** | Exception stack trace containing API tokens is saved to node error fields. | `CredentialStore.redact_sensitive_str()` scrubs tokens and passwords matching regex patterns. | `test_workflow_analytics.py` | **VERIFIED** | String error sanitization. |
| **T-17** | **Malicious Variable Values** | Variable injection contains script tags or SQL fragments. | Context resolution does not execute dynamic code; variables treated as inert JSON strings. | `test_workflow_variables.py` | **VERIFIED** | No eval or SQL interpolation. |
| **T-18** | **Unsafe Expressions** | Attacker crafts `{{__import__('os').system('rm -rf /')}}` in template. | Pure regex parser matching only `input.x`, `variables.x`, `nodes.x.output`; no Python `eval()`. | `test_workflow_variables.py` | **VERIFIED** | Regex reject non-whitelisted paths. |
| **T-19** | **Arbitrary Code Execution** | Local tool node executes unverified system shell command. | Node dispatcher only calls pre-registered safe classes in `ToolRegistry`. | `test_workflow_node_execution.py` | **VERIFIED** | Registry whitelist only. |
| **T-20** | **Poisoned MCP Output** | External MCP server returns malicious injection payload. | MCP nodes flag outputs with `"provenance": "UNTRUSTED_MCP"` for downstream sanitization. | `test_workflow_mcp_node.py` | **VERIFIED** | Provenance tagging active. |
| **T-21** | **RAG Provenance Leakage** | RAG node retrieves context from another tenant's vector database. | Vector query enforces `workspace_id` match and Critic verifies citation workspace integrity. | `test_workflow_rag_node.py` | **VERIFIED** | Strict workspace isolation. |
| **T-22** | **Knowledge Graph Leakage** | Graph node traverses relationships belonging to another tenant. | Graph entity traversal filters strictly by `workspace_id`. | `test_workflow_graph_node.py` | **VERIFIED** | Cross-tenant traversal rejected. |
| **T-23** | **Memory Tenant Leakage** | Memory node recalls agent memories across tenant boundaries. | Memory store isolates facts by `(workspace_id, user_id)`. | `test_workflow_memory_node.py` | **VERIFIED** | Cross-user/tenant isolation. |
| **T-24** | **Child Privilege Escalation** | Sub-workflow executes tools or agents unauthorized for the parent caller. | Sub-workflow execution runs under the caller's verified `user_id` and `workspace_id`. | `test_workflow_composition.py` | **VERIFIED** | Caller identity propagated. |
| **T-25** | **Approval Bypass** | Workflow continues without waiting for HUMAN_APPROVAL decision. | `WorkflowExecutionService` pauses execution with status `WAITING` until explicit approval endpoint call. | `test_workflow_approval_and_cancel.py`| **VERIFIED** | Engine suspends execution. |
| **T-26** | **Stale Execution State** | Old executions linger in `RUNNING` status indefinitely. | Node execution wrapped in try-catch with timeout fallback. | `test_workflow_execution.py` | **VERIFIED** | Terminal status reached. |
| **T-27** | **Cache Poisoning** | Workspace analytics cached under global key, exposing metrics to another tenant. | All analytics queries and cache keys are prefixed with `workspace_id`. | `test_workflow_analytics_tenant_isolation.py` | **VERIFIED** | Per-workspace caching keys. |
| **T-28** | **Redis Lock Misuse** | Deadlock occurs during long execution or crash. | Locks utilize bounded TTLs and auto-expiry. | `test_workflow_scheduler.py` | **VERIFIED** | TTL prevents deadlocks. |
| **T-29** | **Oversized Payloads** | Client posts 50MB JSON payload into workflow inputs. | `MAX_NODES_PER_EXECUTION = 50` and FastAPI request body limits protect engine. | `test_workflow_validation.py` | **VERIFIED** | Bounded payload sizes. |
| **T-30** | **Oversized Context** | Cumulative node outputs exceed memory limits. | Execution context trims intermediate outputs and limits citation lists. | `test_workflow_variables.py` | **VERIFIED** | Controlled context growth. |
